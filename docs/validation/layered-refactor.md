# Проверка упрощённого layered-поиска

Исходник: предоставленный `tidyhebo (3).zip`, HEAD `53c2f34`.
С учётом Windows line endings функциональных незакоммиченных изменений в архиве
не обнаружено. Патч строится относительно этого состояния.

## Результаты

- Полный набор: **328 passed, 6 skipped**, 4 subtests passed (55.08 s).
- Шесть пропусков относятся к CUDA: GPU в этом окружении недоступен.
- Проверены q=1,2,4,8,16; novel/distinct батчи; публичный DataFrame API;
  полный бюджет основного GA и финальные memetic-оценки; grouped/independent
  Adam; сохранение лучшего допустимого restart; копия GP, значения AF,
  производные по координатам и RNG; реальный YJ/input warp fit и suggest.
- AnalyticMACE сверяется по значениям и градиентам с нативными BoTorch
  LogExpectedImprovement, ProbabilityOfImprovement и UpperConfidenceBound.
- Формула Чебышева сверяется с явным вычислением и проверкой градиента.
- Статическая проверка изменённых модулей layered/AF: ruff select F проходит.

Среда: Python 3.12, Torch 2.7.1+cpu, BoTorch 0.14.0, GPyTorch 1.14,
pymoo 0.6.1.5, NumPy 2.2.6, pandas 2.2.3, SciPy 1.15.3, pytest 9.2.0.
CPU/BLAS threads ограничены одним. Для полного набора:

```bash
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 python -m pytest -q
```

## Независимая сверка с исходным кодом

Исходный код запускался отдельно, до подмены его реализаций. Для фиксированных
seed=73, q=4, qmc_seed=19 и малых бюджетов получен свежий исходный фронт.
Новая архитектура с прежней скаляризацией (включая прежнее потребление RNG)
воспроизвела **тот же фронт**, максимальное отклонение координат — **0.0**.
Это проверяет перенос поиска из Stage/обёрток в LayeredSearch независимо от
дальнейшего удаления неиспользуемого Sobol-банка весов.

В исходном Scalarizer создавался случайный банк весов для weighted_sum, хотя
конфигурация допускала только augmented_chebyshev. Этот банк удалён вместе с
недоступными ветками. Формула augmented Chebyshev сохранена, но удаление
потребления RNG меняет последующие случайные Sobol-инициализации. Поэтому
**побитовая идентичность прежних траекторий после этой очистки не заявляется**.

## Архивный эталон

`tests/fixtures/layered_leader_reference.json` оставлен без изменений.
Его прежний тест точных координат не проходит и на предоставленном
**неизменённом исходном коде** в указанной среде: получается 7 батчей против 8
в архивном файле. Причина различия архивного запуска и текущей среды здесь
не установлена; этот результат нельзя приписывать рефакторингу.

Вместо выдачи нового фронта за старый эталон тест явно проверяет повторяемость
двух полных запусков с одинаковыми seed и отдельный новый эталон
`layered_refactor_reference.json` для версии после удаления банка весов.
Старый эталон сохранён как исторический материал. Качество на Olympus и
реальное ускорение на CUDA в этой работе не измерялись.

При некоторых близких точках GPyTorch добавляет Cholesky jitter 1e-8;
предупреждения не подавлены.

## Применение и внешний probe

Патч применён к свежей распаковке исходного архива; содержимое всех 32
затронутых файлов сверено с рабочей версией. На применённой копии тесты
полного layered-поиска и нового эталона: **7 passed**.

Внешний `benchmark-extras/layered_speed.py` проверен на CPU: q=2,
train-size=4, полный preset (48 индивидов, 20 поколений), один прогрев и один
замер. JSON записан успешно. Это smoke-проверка скрипта, не оценка ускорения.
